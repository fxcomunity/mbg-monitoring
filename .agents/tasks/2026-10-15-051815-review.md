# URL fixes, responsiveness, toast replacement for MBG-MONITORING static site

The change set fixes dead `.php` links throughout the Cloudflare Pages static site, replaces the blocking `alert()` form-submit handler with a non-blocking toast notification across all three dashboards, applies mobile-responsive padding and horizontal scroll to dashboard headers and nav bars, and removes four redundant root PHP files plus a duplicate OG image asset. The `_redirects` file was extended to cover additional PHP URLs that may be bookmarked or crawled.

**Watch for (confirmed):** Five public-facing pages (`laporan-aduan.html`, `menu-hari-ini.html`, `distribusi-sebaran-sppg.html`, `kebijakan-privasi.html`, `standar-uji-akg.html`) still carry broken `href="login.php"` and `href="auth/login.php"` "Portal Masuk" nav links — these were omitted from the plan scope but are broken on the live site. The admin dashboard live-chat reply form (`id="adminReplyForm"`) is not in the toast skip-list, so submitting it triggers the demo toast instead of the intended reply handler. Orphan duplicate `arrow_forward` spans remain in Cards 2, 3, and 4 footers of `index.html`; only Card 1 was fixed.

**Verdict**: NEEDS_CHANGES

---

## High-level view

The three dashboard files received the full intended treatment: inline security script carries the toast handler (no `alert()`), form actions point to `#`, header padding is `px-4 sm:px-8`, and avatar src paths in the user dashboard use the correct `../../` depth. The toast skip-list covers the right async forms for SPPG and user dashboards, but misses the admin chat reply form — confirmed via the `id="adminReplyForm"` attribute on line 1064 of the admin dashboard.

The plan scoped URL fixes to `index.html`, `login.html`, `dashboard/*/index.html`, and `script.js`. The five public pages sharing the same nav header template were not in scope. `_redirects` does catch these at the network layer (`/login.php` and `/auth/login.php` both redirect to `/login.html`), so visits won't hard-404, but every "Portal Masuk" click on those pages incurs an unnecessary redirect hop.

The `login.html` header logo `onerror` sets `this.src` to the same value as the primary `src` attribute — a self-loop that will fire continuously on image load failure. The body logo fix was applied correctly; the header logo was missed.

Cards 2, 3, and 4 in `index.html` each still carry an orphan `<span>arrow_forward</span>` after the closing `</a>` in their footer links, rendering a double icon. Card 1 was the only one deduped.

### Admin chat reply form not in toast skip-list

The global submit intercept uses a capture-phase listener and checks `e.target.id` against a hardcoded skip-list before calling `e.preventDefault()`. All three dashboard files share the same skip-list: `['formSatgas','formSppg','formUploadUserAvatar','formUploadSppgLogo','sppgReplyForm']`. The SPPG and user dashboards are correctly covered. The admin dashboard has a live-chat reply form at line 1064 with `id="adminReplyForm"` and `onsubmit="sendAdminReply(event)"`. Because `adminReplyForm` is not in the skip-list, the capture listener intercepts the submit before `sendAdminReply` runs, shows the demo toast, and the reply is never sent. The admin live-chat feature is broken in the current state.

### Missing URL fixes in shared public-page nav headers

All five public pages use the same nav header pattern and were not updated:

- `laporan-aduan.html` — `href="auth/login.php"` (desktop), `href="auth/login.php"` (mobile)
- `menu-hari-ini.html` — `href="login.php"` (desktop), `href="login.php"` (mobile)
- `distribusi-sebaran-sppg.html` — `href="login.php"` (desktop), `href="login.php"` (mobile)
- `standar-uji-akg.html` — `href="login.php"` (desktop), `href="login.php"` (mobile)
- `kebijakan-privasi.html` — `href="login.php"` (desktop), `href="login.php"` (mobile)

The `_redirects` rules for `/login.php` and `/auth/login.php` mean these won't hard-404, but each click incurs a redirect round-trip and the underlying links remain incorrect source.

### Orphan duplicate `arrow_forward` icons in index.html

The plan deduped Card 1 only. Cards 2, 3, and 4 each have this pattern:

```html
</a>
<span class="material-symbols-outlined text-secondary group-hover:translate-x-1 transition-transform">arrow_forward</span>
```

The orphan span is outside the anchor, so it receives no hover state and renders as a detached icon next to the linked arrow. Visually broken on all screen sizes.

### `login.html` header logo `onerror` self-loop

Line 82 in `login.html`:
```html
<img src="assets/images/logo.webp" ... onerror="this.src='assets/images/logo.webp'">
```
The `onerror` handler sets `src` to the same path that just failed. This fires the `error` event again, causing an infinite loop of network requests until the browser gives up. The body logo (`onerror="this.src='assets/images/logo.webp'"` with the same value) has the same defect. The plan noted fixing the `onerror` fallback in `login.html`, but neither logo was corrected to clear the handler before reassigning `src`.
